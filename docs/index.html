paper-fig-deck · 文献逐图精讲 PPTX 流水线 · 使用手册

从一篇论文 PDF 到「左图 + 右大段正文 + 原文引用条 + 逐页讲稿」的可编辑 PPTX
schema_version 2 版面 1280×720 · 正文 ≥24px（18pt） 后端 PPT Master（MIT）· 可替换 96 项测试 · CI 3.10/3.11/3.12

本手册面向「要用它出片」的人和「要维护它」的人，各占一半篇幅。 它回答三个问题：怎么最快跑通一次、每一页的文字该长什么样、出问题该看哪里。 所有命令、数值和输出都是在本仓库当前版本上真实执行过的，不是示意。

01它做什么 / 不做什么

输入一篇论文（PDF + 你自己写的 content.json），输出一份逐图讲解的 PPTX： 每一页左边是论文原图，右边是一大段中文解读，底部一条原文引用，讲稿在备注里。 适合自学精读和组会汇报，不适合当海报或答辩模板（那是别的版式）。

它保证什么

每页正文不溢出、不压线、不超面板；字号不低于 18pt；页数与讲稿数严格 1:1；原生表格可编辑；成品 PPTX 落盘后再做一次结构审计。

它不保证什么

内容对不对。提炼是否准确、数字是否与原文一致、论证是否成立，全部由作者负责——流水线只保证「按你给的内容排版正确」。

02五分钟上手

先装环境，再用仓库自带的合成样例跑一遍。样例是一篇虚构论文（虚构材料代号、虚构期刊与 DOI、脚本画的图）， 专门用来验证链路，不碰任何真实文献。

# 1. 项目与依赖（任意 Python ≥3.10 venv）
git clone <本仓库> && cd paper-fig-deck
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt      # Linux/macOS: .venv/bin/pip

# 2. 后端：ppt-master（MIT）。放任意位置都行
git clone https://github.com/hugohe3/ppt-master /path/to/ppt-master
export PPTMASTER_DIR=/path/to/ppt-master           # Windows: setx PPTMASTER_DIR ...

# 3. 自检：缺什么、怎么补，一次说清
python pipeline/doctor.py

# 4. 冒烟测试：不需要 ppt-master，只验内容与生成器
python pipeline/run_pipeline.py sample --dry-run

# 5. 完整链路：门禁 → 导出 → 后处理 → 校验
python pipeline/run_pipeline.py sample --name demo

第 5 步成功时，尾部一定长这样（数字会随内容变，三个断言不会变）：

[5/9] gate clean (blocking=0, warnings=3)
[7/9] post-processed -> output\demo_逐图精讲.pptx
[8/9] VERIFY slides=10 notes=10 overflow=0 native_tbl=1 media=3
[9/9] delivery -> output\demo_逐图精讲.pptx
跑通了就把 sample/ 换成自己的 workdir。 每篇论文只有三步：填 content.json → 跑一条命令 → 看 VERIFY。 样例的 content.json 就是填空模板：两个图页（其中一个正文长到会自动拆「续页」）+ 一个表页。
--dry-run 的产物不可交付。 它用的是近似宽度模型（CJK 1.10em / Latin 0.62em），只用来证明「内容与生成器对得上」。 正规生成会强制要求真实后端，否则直接报错 —— 这是刻意的：按错的模型排出来的版面，在 PowerPoint 里会溢出。
想让它变成 agent 自动执行的技能？ 仓库自带薄壳技能 skill/paper-fig-deck/（只有触发条件、入口命令、硬规则与 排错表，不含代码）。把整个目录拷进 Claude Code / Hermes / OpenClaw 的 skills 目录，再设 PAPER_FIG_DECK_DIR=<repo> 指向本仓库即可；CI 会校验它的 frontmatter、引用路径与描述长度。细节见 docs/agent-install.md §11。

03一次构建的 10 个步骤

run_pipeline.py 把顺序坑固化成一条命令。你只需要知道「哪一步会停、停了改什么」。 编号是 第 0 步校验 + 1–9；第 2 步实际由两件事组成（清旧讲稿、图片入项目），下表拆成 2 与 2b 便于对照日志。

步动作做什么 / 为什么必须在这个位置
0校验content_schema.validate()：字段缺失、类型错、表格行列不匹配、行数超版面 —— 报出精确路径，在写任何文件之前就停。
1项目读 content.json[paper][ppt_project]；目录不在了就用 project_manager.py init 重建，并把新路径写回 content.json（从工具打印的 Project created: 行解析，不靠猜路径）。
2清旧讲稿删 notes/*.md。必须在拆分之前：total_md_split.py 的 1:1 检查会把上一次的残留算进去。
2b图片入项目
第 2 步的子步		有 figures.json 按图表编号压成 figNN.jpg；否则把 images/ 里的 jpg/png 原样 stage 进 <project>/images/（≤2000px、≤900KB）。
3生成gen_all（SVG）→ gen_notes（讲稿）→ total_md_split → compact 样式 → compact 坐标。
4原生表标记只对含 kind:"table" 的稿子：stamp_native_fallbacks --write，必须在 compact 之后、门禁之前（compact 会重写 SVG，SHA 会失效）。
5门禁svg_quality_checker --stage final --json；结论只认 validation/svg_quality_report.json，不看 stdout。blocking>0 直接拒绝导出。
6导出svg_to_pptx --quick-generate --with-notes --reflow-text（有表再加 --native-charts-and-tables）。导出文件用 ls -t exports/*.pptx 取最新的，不解析 stdout（里面是反斜杠路径）。
7后处理postproc_justify：把正文框宽还原成版面宽度、加 algn="just"、加 36pt 首行缩进 —— 这三件事 SVG 表达不了，只能在 PPTX 里做。
8成品审计页数 / 讲稿数 / 越界形状 / <a:tbl> 数 / 媒体数；三个断言不过就抛错。
9交付输出到 <workdir>/../output/<name>_逐图精讲.pptx；--desktop-dir 可再复制一份，文件被占用时只警告不失败。

常用开关

开关用途
--name交付文件名（默认取 workdir 名）
--dry-run只做校验 + SVG + 讲稿，用近似宽度模型写到 <workdir>/.dryrun；不可交付
--no-export门禁通过就停 —— 反复改文案时最省时间
--project-dir覆盖 paper.ppt_project（多个 workdir 共用一个项目时用）
--skip-validate跳过第 0 步。只在调试生成器本身时用，正常不要碰
--desktop-dir额外复制一份到指定目录

04content.json 字段参考

这是整套流程里唯一需要你动脑的文件。怎么写出「像作者的论证」而不是「像结果清单」， 见 pipeline/content_rules.md；这里只讲字段怎么填、填错会怎样。

字段必填说明
schema_version建议当前 "2"；缺省会当作 "1" 并给 warning
paper.title_zh / journal /
authors_short / doi		是封面与页脚用。做样例时也要给虚构值（公开仓库不能出现真实文献信息）
paper.title_page_img是封面图文件名，须存在于项目 images/
paper.abstract_zh /
conclusion_zh		是中文摘要与结论，各 ≤10 行（全宽 1184px）
paper.intro_lines否五线分析：[["背景与研究现状","…"], …]，≤5 条，整页 ≤16 行
paper.mainline否论证主线：[["Fig 1","它证明了什么"], …]，与 figures 顺序对齐；有它才生成总览页
paper.methods_zh否制备方法整页（≤12 行）
paper.message /
takeaway_good / if_rebuild		否只进讲稿：三十秒读法、好在哪、若重做会怎么改
paper.title_crop否{pdf, page, rect:[x0,y0,x1,y1], out, z}，让 prep_images 从 PDF 直接裁封面
figures[].kind是figure / scheme / table（三种都会渲染；table 走左表右注）
figures[].num / img是 / 否图号；img 缺省为 figNN.jpg
figures[].slides[]是图：{reading_point, what, body, quote, quote_ref}；表：{reading_point, table_note, headers, table_rows, quote, quote_ref}
figures[].arguing / critique否只进讲稿：【论证】这一步如何立论、【批判】证据强度与回避的问题
正文怎么写：一个 body 只讲一个读点。超过 14 行会自动拆成「（续）」页，但那是兜底，不是目标 —— 拆页会打断阅读节奏。reading_point 是右面板标题，单行；放不下时第 0 步直接报 error（标题被裁掉等于丢信息，不让它悄悄发生）。quote 最多 3 行，超了同样报 error —— 请换一个更短的完整句，而不是让页面显示半句。

机器可读版本：pipeline/schema/content.schema.json（IDE 补全 / agent 自检都能用）。生成方式：

python pipeline/content_schema.py --write-json-schema pipeline/schema/content.schema.json

05版面契约

所有几何数字集中在 pipeline/layout.py —— 生成器、后处理器、测试共用同一张表。 改一处即全链路生效；在别处写字面量算 bug。

元素参数（SVG px，画布 1280×720）
字号全部 ≥24px（= 18pt）；标题 32px；页脚 24px
左图卡(48,144) 568×496；图按 meet 落在 (64,160) 536×464
右面板(640,144) 608×530；文字起点 x=668，换行宽 552
正文区y212 → y548；实测 14 行封顶，行距按行数自适应（min(36, 336/n)）
原文条y556 细分隔线 → y582 标签 → y608 起最多 3 行引用（行距 28）；超出 3 行在第 0 步报 error，页面上不会出现「…」半句
表格页表格 (48,160) 730 宽、行高 48、≤8 行；右注栏 x=828，宽 376
总览页每行一个模块；≤9 行单栏（1184 宽），>9 行双栏（560 宽）；标签列固定 132px，保证所有 claim 起点对齐
颜色BLUE #1F3864 · GOLD #C9A227 · DARK #333333 · GRAY #595959 · LGRAY #8A8F98
字体Times New Roman + 宋体（SVG 根节点声明，导出后写入 PPTX 主题的 latin/ea）
14 行不是猜的。measure_capacity.py 用 PowerPoint COM 在真实导出几何里渲染 12/13/14/15 行的正文， 再按像素扫描墨迹底边与 y556 细线：14 行墨迹止于约 552px，15 行到 584px（溢出）。 换字体、改盒宽、改行距之后，必须重跑 measure 并更新 layout.py，不要凭感觉改数字。

06校验器：error 与 warning

第 0 步的校验把问题分成两类。这套分级是刻意的：error 会让流水线停下，warning 不会， 但 warning 通常意味着「能建出来，但大概不是你想要的」。

级别典型触发为什么这样分级
error必填字段缺失/空串 · figures 为空 · kind 不在三种之内 · 表格行列数不匹配 · 表格超过 8 行 · 列数 >6 · schema_version 不支持 · 引用超过 3 行 · 读点题名放不下一行这些会让页面缺内容或直接崩，没有「先建出来看看」的余地
warning正文 >1400 字 · 单元格 >24 字 · mainline 条数与 figures 不一致 · 缺 schema_version · 机器上没装后端时的宽度类检查（近似模型不阻塞）建得出，但会拆很多页 / 部分图拿不到主线注释
# 单独跑校验（比整条流水线快得多）
python pipeline/content_schema.py <workdir>          # 退出码 1 = 有 error
python pipeline/content_schema.py <workdir> --json   # 机器可读，便于 agent 循环修
python pipeline/content_schema.py <workdir> --stage build   # 额外要求 ppt_project 已填

报错长这样，直接照路径改：

[error] figures[2].slides[0].table_rows[2]: 3 cells for 4 columns
[error] paper.doi: required non-empty string
[error] figures[0].slides[1].quote: needs 4 lines at 552 px; the quote band shows at most 3 — the page must not clip a citation, so quote a shorter complete sentence (about 110 chars)
[error] figures[2].slides[0].reading_point: the note-column title is one line and must not be truncated (~14 CJK chars at 376 px)

07验收与质量保障

五道闸门，各拦一类问题。除第三道外，其余都在本地可复现，不需要 PowerPoint。

层手段拦住什么
输入content_schema.py字段名错、缺必填、表格行列不匹配、行数超版面
版面layout.py + tests/test_layout.py模块重叠、图片超出卡片、字号掉到 18pt 以下
排版复用后端的宽度估算器（与门禁同模型）SVG 看着正常、PowerPoint 里却溢出的情况
门禁svg_quality_checker（blocking > 0 拒导出）越界、图文重叠、非法图片引用、未声明的字号
成品verify_pptx()slides ≠ notes、形状出界、原生表没落地

自己跑测试与静态检查

pip install -r requirements-dev.txt
ruff check . && pytest                     # 本机：真实宽度模型
PAPER_FIG_DECK_NO_BACKEND=1 pytest          # 模拟没装 ppt-master 的机器

第二种模式很重要：CI 就是用它跑的。PAPER_FIG_DECK_NO_BACKEND=1 会强制走近似模型， 保证「新机器 clone 下来什么都没装」这条路径永远可测 —— 否则本地有 ppt-master 就永远测不到它。

最后一关仍是眼睛

门禁证明坐标合法，不证明像素正确（中文字形比估算宽、tspan 续行可能叠字）。 交付前至少亲眼看三类页：总览页（对齐）、最长正文页（是否压线）、表格页（列宽是否裁字）。 做法：把 SVG 用本地 http 服务打开，或直接打开导出的 PPTX 翻一遍。

08排错手册

症状原因处理
[error] … no ppt-master scripts/ dir found后端没装或路径不对设 PPTMASTER_DIR（指向含 scripts/svg_quality_checker.py 的目录），跑 doctor.py 看它找到了哪
content.json has N error(s)内容字段问题按打印的字段路径改；--json 便于脚本处理
BLOCKING: … External image not found图片没进项目 images/确认 workdir 里有 images/ 或 figures.json；驱动会自动 stage
BLOCKING: … exceeds <g id="panel">
… horizontal axis		单行文字比面板宽缩短文案；读点题名与引用在第 0 步就被拦，正文靠行数上限控制
notes/svg mismatch讲稿与页面没 1:1驱动会先删旧讲稿；手工跑时要自己清 notes/*.md
VERIFY … overflow>0PPTX 里有形状出界多半是正文框宽被改过；检查 page_roles.json 与 postproc_justify
native tables requested but no <a:tbl>导出时少了原生表开关确认走 run_pipeline.py（它按内容自动加 --native-charts-and-tables）
Linux 上 pip install 失败（pywin32）旧版 requirements 没有平台标记已修：pywin32>=306; sys_platform == "win32"
导出的 PPT 字体变成了别的本机没有 Times New Roman / 宋体装字体；SVG 只声明字体名，渲染在 PowerPoint 侧
改字之后：重跑同一条命令即可。项目目录会复用，SVG 与讲稿全量重生成， 不用担心残留页——第 2 步和第 3 步都会清。

09换一个后端

流水线本身只负责「产出 SVG + 讲稿 + 版面数据」，PPT 工具链是可替换的。 需要满足五项能力，缺一不可：

能力PPT Master（推荐）对应件
文本宽度估算svg_to_pptx.drawingml…estimate_single_line_text_frame_width（与门禁同模型）
SVG → PPTXsvg_to_pptx.py --quick-generate --with-notes --reflow-text [--native-charts-and-tables]
质量门禁svg_quality_checker.py --json（写 validation/svg_quality_report.json）
备注拆分total_md_split.py（与 SVG 1:1 校验）
原生表标记stamp_native_fallbacks.py --write

换工具链时只需要改两处：kit.py 的后端解析（_resolve_estimator）和 run_pipeline.py 的步骤命令。路径通过 PPTMASTER_DIR / SKILL_SCRIPTS_DIR 注入， 也可以靠自动发现（常见安装位置、Hermes profile 的 skills 目录）。

10版权红线

  • 源 PDF、content.json、figures.json、裁剪图、交付 PPTX —— 只留本地，永不提交
  • 公开仓库（含 git 历史与 LICENSE）不得出现任何文献信息：作者、期刊、卷期、DOI、材料名、篇内数值 —— 开放获取（OA）的也不行
  • 仓库里没有、也不应该有个人路径与账号信息；仓库自带的 sample/ 是纯合成内容（虚构材料代号、虚构期刊与 DOI、脚本绘制的图）
  • 对外回复时不复述论文原文片段；数据核对在本地完成
为什么这么严：这是「工具仓库」，不是「文献仓库」。 一旦某篇论文的作者名或图进了公开历史，清洗成本远高于一开始就不放。 想演示，就用 sample/ 那样的合成数据。
